Closes #700

## Summary

Audits every group administration endpoint against the RBAC contract in CONTRIBUTING.md ("every group action must check membership; admin-only actions must check the role") and closes the two gaps that audit found.

## Audit result

All group-scoped mutations already enforce membership via `requireMembership` / `requireAdmin` in `src/services/access.ts`, which reads the role from the database membership row — never from request data. Endpoints verified admin-gated: invite (both shapes), member role change, member removal, archive, treasury enable, treasury withdraw confirm, treasury proposals, audit log (group scope), webhook delete. Endpoints verified member-gated: expenses CRUD (payer-or-admin for edit/delete), settlements, balances, ledger, history.

Two real gaps remained:

## Changes

### 1. `DELETE /groups/:id/members/:memberId` — admin check moved inside the transaction (`src/routes/groups.ts`)

The `requireAdmin` call ran *outside* the removal transaction, unlike invite, role change, and archive which all check inside (documented in the route as the atomicity convention). A caller demoted between their own authorization check and the transaction could land one last unauthorized removal. The check now runs inside the transaction with the same `tx` client, so a concurrent demotion cannot slip an ex-admin's removal through.

### 2. Group webhook registration requires admin (`src/routes/webhooks.ts`)

`POST /api/webhooks` with a `groupId` (and the legacy `POST /groups/:groupId/webhooks`) accepted **any member**, letting a non-admin stream the group's financial events (settlements, expense changes, settlement completions) to a caller-supplied URL — an exfiltration channel indistinguishable from a compromised admin account. Registration now:

- requires admin, matching the bar of treasury withdrawal and member removal (webhook *deletion* already required admin — creation was the asymmetry)
- runs the admin check and the insert in one transaction, so a caller demoted mid-request cannot register an endpoint
- writes an audit record (`webhook.register`) with actor, group, URL, and events

Personal (group-less) registrations are unchanged: they only ever receive the caller's own events.

- [x] Non-admin members attempting admin actions receive 403 Forbidden (and non-members 403/404 per the deliberate existence-leak policy in `src/services/access.ts`)
- [x] Unit and integration-style route tests cover both admin and standard member access attempts (new `tests/routes/group-removal-rbac.test.ts`; updated `tests/routes/webhook-registration.test.ts`)
